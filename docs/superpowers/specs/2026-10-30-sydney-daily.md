# 悉尼补齐与每日运行

用户已要求在既定预算内继续完成悉尼、恢复每日网站更新，自主推进。沿用 Python 爬虫、正式 SQLite 账本、现有受限 MySQL 写入，不扩大区域或改变线上表。

- 只处理原 UNSW / USYD / UTS 区域与真实查询学校归属；墨尔本继续暂停。
- 模型仅新专用固定 Flash，CNY 50/月；非模型 USD 4/月，通勤新增现金 0，既有 Distancematrix.ai 赠金累计最多 USD 40，不能购买或自动充值。
- 只复用爬虫机原账本，成功路线按完整地址与学校跨来源复用；模型完整缓存及已完成槽位保留。旧失败、不确定、暂停和费用预留不删除。
- 新模型先真实小样本、再零新增调用复验。费用、8 个评分及双语关键词通过后才能恢复分批任务。
- NSW 优先。仅对其未得到成功路线的悉尼记录，显式启用 Accurate 公交赠金接口；每请求严格 1 起点 × 1 终点，HTTP 前原子预留赠金额与次数，超时/拒绝也保留，不自动重试，不转现金。
- 提供商返回错误地址、空结果、无公交路线或不完整模型时保留缺口，不能伪造完整。
- 旧批次中 held 与未处理输入生成新冻结恢复任务；排除已发布 ID，保留旧回执，不能直接把旧 processed 当作已补齐。
- 每日采集后按真实学校 cohort 去重；模型关闭时仍可做免费通勤和缓存发布。提供商错误立即停止模型请求，后续只能用显式跳过模型的路径继续。
- 每次生产 DML 前备份；核对 MySQL、公开 API、页面。夜间调度需实际一次运行回执，不能只看 cron 存在。
- 对大体积旧数据库备份只做无损压缩，逐个校验解压 SHA256 后替代原文件，正式数据库及 API 缓存不动。

选择沿用现有管线并增加受控赠金补缺；重新全城采集或切换线上表不符合用户已经确定的范围。实现细节由本轮决定，不额外要求用户审批常规步骤。
