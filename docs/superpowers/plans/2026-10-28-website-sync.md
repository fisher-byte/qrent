# Qrent 官网真实库存同步

目标：来源页面 → 当前采集库存 → 发布校验 → 官网数据库/API → 实际房源卡片，逐段验收。不得把采集成功、导入成功或抓取日期单独当成官网已经更新。

## 已确认的断点

- `www.qrent.rent` 为 Vercel 前端，公开 `api.qrent.rent/trpc/properties.search` 正常响应。
- UNSW 查询 743 条，USYD 558，UTS 319，UNIMELB 535；最新记录仍为 2026-05-13。截图 Newtown / $1050 / Domain 18115070 与实时 API 完全一致，未出现在本轮采集库存。
- 当前腾讯云爬虫机没有官网 MySQL/backend 服务；已连接的 HK relay 也未发现 Qrent 部署。官网部署地址/数据库连接配置待用户提供，已异步询问，不更改未知数据库。
- 全量与增量合并候选为 59,364 个平台来源 ID；整库还含 1,521 条范围外历史记录。
- 全部候选缺来源发布时间、全部缺通勤，绝大部分未评分。15 条异常大价格、14 条未知价，153 条低价需要复核。旧日期导入会把 ISO/空值填为现在，必须修复。

## 实施与验收

1. [x] 保存官网实时 API、时间、计数和样本，完成来源库独立审计。记录覆盖规则及市场变化的边界，不宣称绝对无遗漏或全部都是独立房屋。见 `docs/reports/2026-10-28-website-sync-audit.md`。
2. [ ] 修复价格/日期解析。保留原始报价与可入住文本；缺失或解析失败为未知，来源发布日期与采集/写入时间分开。以真实异常样例验证。
3. [ ] 生成默认 dry-run 的发布数据集：只取成功 campaign 的 ID union，跨州地区按 suburb/state/postcode 区分，异常报价隔离；评分/通勤/发布时间保留空值，不填 0 或今天。输出逐项接受/隔离/缺失计数与来源样本。
4. [ ] 获得目标后端连接后先只读确认实际 schema、学校关联、缓存与部署版本，备份后迁移并分批幂等 upsert；保留账户、收藏和旧 property 主键，不清库。
5. [ ] 官网提供基础库存入口，不依赖虚构的学校通勤；未知日期显示采集时间，未知价格/评分/通勤明确展示为未知，源链接和原始报价可核对。
6. [ ] 验证四组来源/城市计数、实际 API 的新增 ID/价格/时间、原始房源抽样、官网搜索/卡片；接入每日采集后的自动发布和发布失败状态。

## 当前发布边界

- 现有数据为平台列表的抓取窗口，不是结束瞬间零遗漏的市场快照，也不验证每条已出租/下架状态。
- 未拿到源发布时间时不伪造“今天发布”；可使用真实 `scraped_at` 标记“采集于”。
- 仅有历史 AI 分数时不当作平台实测评分；不批量调用模型或地图收费接口来填充空值。
- 新房源缺学校关联时不能静默过滤掉，也不能用 0 分钟创建虚假通勤。
